# 02 Offer and Pricing Governance

## Purpose

This document is the authoritative source for Studio Las offer and pricing governance.

It exists to prevent public pages, README files, forms, old offer pages, or implementation artifacts from independently defining the offer.

It does not define the full Studio Las Method.

It does not define UI.

It does not define sales copy.

It defines the current canonical offer truth and the rules for projecting that truth into public surfaces.

## Authority

This document is subordinate to:

1. `docs/constitution/README.md`
2. `docs/governance/00_SOURCE_OF_TRUTH_REGISTRY.md`
3. `docs/product/README.md`
4. `docs/product/00_PRODUCT_MODEL.md`
5. `docs/product/01_CLIENT_JOURNEY.md`

If this document conflicts with Constitution or Product, Constitution and Product win.

If website pages, forms, README files, or app copy conflict with this document on price or offer structure, this document wins.

## Core product boundary

Studio Las sells a trainer-led method.

Studio Las does not sell app access.

Studio Las OS is not priced as a separate product.

The client pays for guided work with the trainer, not for software.

## Current canonical price

The current official price for the First Diagnostic Visit is:

> 300 PLN

This is the canonical price until a future governance decision changes it.

Any public surface showing 400 PLN is stale and must be treated as an outdated projection.

## First Diagnostic Visit role

The First Diagnostic Visit is the entry point into the Studio Las process.

Its role is to help the trainer and client understand:

- current functional starting point,
- movement confidence,
- relevant limitations,
- basic safety constraints,
- whether Studio Las is an appropriate next step,
- what kind of guided process may make sense.

The visit must not be framed as:

- a generic training session,
- a medical diagnosis,
- an app onboarding session,
- a sales trick,
- a paid consultation only to sell software.

## Deduction rule

The current accepted offer allows the 300 PLN First Diagnostic Visit fee to be deducted from the 12-week program when the client decides to enter that program within seven calendar days after receiving the trainer-reviewed PWD summary and recommendation.

The seven-day window exists to support an informed decision. It must not be presented as artificial scarcity, same-day pressure, or a countdown mechanic. One respectful reminder is permitted; silence is not consent and does not justify repeated calls.

This condition must be communicated consistently wherever it appears. If the deduction condition changes, this document must be updated before public pages, forms, messages, or sales materials are changed.

## Offer ownership

This document owns:

- diagnostic visit price,
- diagnostic visit offer boundary,
- package-level pricing governance,
- rule that OS/app access is not sold separately,
- rule that website pages are projections of offer truth.

This document does not own:

- detailed page copy,
- marketing wording,
- UI layout,
- payment processing,
- tax/accounting implementation,
- package contract language,
- legal terms.

Those may require separate documents or legal review.

## Public website projection rule

The website may publish the current offer.

The website may not define the offer independently.

If a website page shows a price, package rule, deduction rule, or diagnostic visit description, it must match this document.

Known stale public projections to audit after this document:

- pages showing 400 PLN,
- duplicate offer pages,
- outdated package descriptions,
- pages where the app appears too central,
- pages where reports are framed as proof/dashboard rather than pattern/decision.

## README projection rule

README files may summarize current offer state only for project orientation.

README files must not become the offer authority.

If a README and this document disagree, this document wins.

## Forms projection rule

Forms may reference the diagnostic visit or process only as an intake/contact path.

Forms must not define pricing, package rules, privacy promises, or medical scope independently.

If form copy contains pricing or offer claims, it must match this document and Privacy/RODO governance.

## OS/app projection rule

Studio Las OS may reflect client status or process access.

Studio Las OS must not define price, package structure, payment status, or commercial eligibility unless a future PRD explicitly scopes that behavior.

App access must remain subordinate to the active Studio Las relationship.

## Pricing change rule

Before changing price, answer:

1. What is the new price?
2. Why is the price changing?
3. Does the change affect positioning of Studio Las?
4. Does the change affect diagnostic visit scope?
5. Does the change affect deduction rules?
6. Which public pages must be updated?
7. Which forms must be updated?
8. Which README summaries must be updated?
9. Does the change require legal/accounting review?
10. Has this document been updated before downstream projections?

No downstream file should be updated before this document changes.

## Cleanup rule

When cleanup begins, update projections in this order:

1. Public homepage and primary CTA path.
2. Contact/diagnostic form path.
3. Active offer/package pages.
4. Stale duplicate offer pages.
5. Oncology or specialized pages that mention price.
6. Metadata, schema, FAQ, or structured content if price appears there.
7. README summaries if needed.

Do not combine pricing cleanup with redesign, copy overhaul, PRD work, Supabase work, or app changes.

## Final rule

Studio Las pricing must be governed by one document, then projected consistently.

The price is currently 300 PLN.

No HTML page may override that truth.
